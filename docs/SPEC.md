# Liubai Taskboard 规格

## 范围

Liubai 是一个个人规划看板：长期目标、周计划、日计划和专注块。界面是一个终端（见「终端界面」）：屏幕上只有当前场景，所有操作经由提示符或等价的点击完成；移动端同一套终端，侧栏收为顶部一行。默认中文，可切换英文；语言与配色只保存在浏览器本地偏好。

## 数据规则

- 长期周期也是项目边界：长期、周、日任务均保存 `cycleId`，周/日分别另带 `weekKey` / `dateKey`。周任务可跨多周：可选的 `endWeekKey` 是最后一周（含），必须晚于 `weekKey`（单周任务不写它，同一跨度只有一种写法）；只有周任务能带它，子任务的跨度与父任务一致。日任务同理可跨多天：可选的 `endDateKey` 是最后一天（含），必须晚于 `dateKey` 且同在一个 ISO 周（周一到周日）——日任务挂哪个周计划才只有一个答案，跨周的事交给周计划。同一周、同一天的不同项目不共享任务；无上级关联的独立任务同样归属于创建时的项目。子任务、上级候选、排序和顺延均保留该边界；专注块仍按日期共享，计时器仍全局最多一个。
- 旧周/日任务的归属只沿已有 `upperTaskId` / `parentId` 恢复，规范化后随下次 CAS 持久化，后续解除关联不会丢失归属。无法确定归属的任务保留在独立「未归属计划」入口，不按重叠日期或当前选中项目猜测，也不删除。旧顺延副本可能后来改换或解除关联，因此历史 `rescheduledTo` 保留，不据此强制跨项目改关联。
- 失败任务草稿记录原始项目及周/日放置，切换项目后重新打开编辑器仍回到原归属；不能把 A 的失败新增写进 B。
- 长期目标、周任务、日任务是独立实体。周任务最多关联一个长期目标，日任务最多关联一个周任务；一个上级可有多个下级。关联不自动同步标题、状态或完成度。
- 每个规划域支持手动勾选、编辑、删除、添加一个层级的同级子任务和同级上下移动。子任务不能再有子任务，也不能跨域关联。
- 删除上级任务时只解除下级的 `upperTaskId`，不跨域级联；删除任务前若仍有子任务，界面必须要求明确确认。专注块引用的任务被删除时只移除引用。
- 任务的计划位置是当前放置；重排计划不会隐式完成任务。

## 删除项目

- 入口是 `/project rm`（作用于当前项目）。先打印项目名称、包含子任务与归档的任务总数、云端回收站保留 30 天（演示模式不可恢复）的说明，以及专注块保留说明；有任务时提示符要求逐字输入项目名称，空项目只需 `[y/N]`。名称不一致不删除，`Esc` 取消。
- `deleteCycle` 一次删除周期及所有归属于它的长期、周、日任务（包括已完成、子任务与归档），与单任务删除复用引用清理。其他项目和未归属任务不删除，遗留跨项目顺延指针仅解除引用。共享专注块只移除被删任务引用，不改变标题、计时状态、时间戳或累计时长。
- 使用现有快照 CAS；`006_agent_access.sql` 在数据库层统一捕获删除并写入回收站与审计。离线、有在途／失败改动时禁止开始删除；确认期间版本变化会清空名称确认，提交时再次检查快照未变。涉及本项目的远端新增或编辑必须重新加载、确认，不自动扩大删除范围；失败沿用直接操作的重试和冲突恢复入口。
- 删除后切换到剩余项目；最后一个项目删除后仍可新建项目、访问未归属计划和专注块。

## 排序

- 拖拽已由命令取代：`/mv <ref> up|down|top|bottom`，导航模式下 `J/K`，展开行里的 `[K] 上移` / `[J] 下移`。
- 只在当前放置的同级列表内排序，父任务携带子任务整体移动；子任务只在同一父任务下排序，不跨域转换实体、不更改关联、日期或完成状态。
- 每次移动提交一次现有快照 CAS；`up/down` 带 `reorderOrigin`，冲突后加载最新再把同一次移动重放到新版本，不覆盖远端改动。
- 项目顺序就是 `cycles` 数组顺序，`/project up|down` 调整当前项目，随同一条快照 CAS 持久化；只重排项目本身，不改变任何任务的归属、日期、内容或未归属计划入口。

## 周期和重排

- 长期周期为自定义含首尾日期的范围；周使用 ISO Monday-Sunday 周；日使用本地日历日期。
- 跨周任务在 `weekKey..endWeekKey` 的每一周都出现：周视图、周条带的 `●○`、目标视图的周分布、日视图的上级、日任务的关联候选与 MCP `tasks_list` 的 `weekKey` 过滤都按“跨度覆盖这一周”判断；周视图里七天分布只数正在看的那一周。行首标出跨度（如 `W40..W42`）。同一视图里同时出现的周任务（跨度相交）可以互相排序。
- 跨天日任务在 `dateKey..endDateKey` 的每一天都出现：日视图、日条带的 `●○`、周视图的七天分布与 MCP `tasks_list` 的 `dateKey` 过滤都按“跨度覆盖这一天”判断；行首标出跨度（如 `10-05..10-07`）。`/start` 给跨天任务开的专注块记在正在看的那一天。
- 日期键以浏览器设置的时区解释。日期运算在 UTC noon 进行，避免 DST 导致日期漂移；时间戳始终保存 ISO 时间戳。
- **未完成的过去任务在载入时自动顺延到当前周期**：周任务把跨度延长到本周（`endWeekKey` = 本周，原地修改，不归档、不复制）；日任务起点在本周的延长到今天（`endDateKey` = 今天），起点在更早的周则归档后复制到今天——日跨度不能出周（`carryForwardTasks`，在 `openBoard` 里用同一条 CAS 保存路径提交，失败/离线走既有重试与提示；顺延本身出错只记日志，不拖垮加载）。不做交互确认，也不再有顶部确认条。
- 周任务延长而不是复制：过去几周仍看得到它，挂在下面的日任务关联不变，每一周的执行轨迹都留在那一周里。只有跨度的最后一周已过去才算过期（行尾 `!`）。
- 自动顺延只处理未完成的顶层任务（已勾选的不动，子任务随父任务起块处理），并且是幂等的：连续载入不会产生新副本，也不会重复延长。
- 顺延目标必须仍在所属项目周期内（周按相交 ISO 周判断，跨度的首尾都要在内）；已结束项目的未完成计划留在原位置，避免自动移出可导航范围。手动越界顺延会提示先调整项目起止日期；未归属计划不受项目范围限制。
- 旧版已顺延到项目外的任务不隐藏：导航范围扩展到本项目已有的未归档周/日任务位置，项目本身的起止日期不变，越界日期仍不能新建或继续向外顺延。其他项目的任务不会扩展当前项目的导航范围。
- 手动顺延（以及旧版自动顺延）会把周任务归档成副本链；还活着的日任务会把 `upperTaskId` 改指周任务现有的副本——追 `rescheduledTo` 链，所以以前搬走的周任务也能被找回。不改指就会挂在已归档的旧周上，场景里的连线会静默消失（不可见的上级被当作未关联）。链尾不是未归档的顶层周任务（断链、成环、指向日任务或子任务）时不动，否则写入会被校验拒绝，进而让整批顺延被放弃。
- 手动顺延仍保留（自动顺延没落地时的兜底：保存失败、离线，或想手动微调）：旧任务保留为 `archivedAt` + `archivedReason: rescheduled`，其 `rescheduledTo` 指向新任务，因此重复顺延会形成可审阅链，不会覆盖原放置，也不会复制同一次操作。入口是 `/defer <ref> [日期|周次]`（过期行尾标 `!`，展开行有 `[r] 顺延`）：日任务用 `rescheduleDailyTask`（默认次日），周任务用 `rescheduleWeeklyTask`（默认下周，跨周任务整段平移、保持周数），子任务随父任务一起顺延。
- 任务不再保存放置历史：`history` 字段已移除（编辑器里的展示面板因无消费者被删掉，展示的是重复信息）。归档条目本身仍然保留原放置位置，因此“旧放置”这一事实有唯一来源。

## 专注块

- 默认 45 分钟，首次开始前可改；时长必须为有限正数且不超过 24 小时。
- 支持添加、分配日任务、开始、暂停、恢复、完成；完成不勾选任务。结束和累计毫秒数都持久化。
- 运行中用 `startedAt` + `elapsedMs` 计算，不依赖 interval tick 累加；后台、刷新、关闭页面不会自动暂停，重开后按时间戳恢复。到时 UI 显示完成态，但必须由用户保存/结束状态，任务不受影响。
- 到点后读数不停在 `00:00`，而是写超出了多少（`+03:12`）；结束时记下实际时长，超时不截断（只受 24 小时上限约束）。运行中标签页标题就是这块钟（`◉ 52:12 标题`），到点后换成 `⏰ +03:12 标题`——计时多半是在别的窗口里跑完的。
- `/start <日任务>` 不给时长时接着这件事当天没做完的那块（正在跑的、做了一半的、还没开始的依次优先），给时长才新开一块：暂停后再开始不会变成两块。已有别的计时在跑时，提示符先问 `暂停 f2 …，开始 f5 …？[y/N]`，答应了才在同一次提交里暂停旧的、开始新的；被校验拒绝时不回显成功。`/stop [ref]` 可以直接结束暂停中、做了一半的块，不必先继续再停止。
- 一个用户在所有设备和所有日期上最多一个运行计时器。客户端先提供即时错误；数据库 RPC 在事务内以 CAS 和约束再次拒绝竞争写入。

## 持久化与冲突

- 每个认证用户一行私有 board JSONB，带单调递增 `revision`。每次变更（含计时器）都在同一条受保护路径中以客户端加载的 revision 做 compare-and-swap；禁止无条件 overwrite/upsert。
- 数据库验证 schema、大小、任务图、日期/时长、运行计时器数量。存入 React 前客户端也验证外部状态。
- 版本冲突使用 SQLSTATE `PT409`（PostgREST 映射为 HTTP 409）。**不要用 `40001`**：它属于 serialization_failure，平台会视为可重试并自动重试，导致每次正常冲突都重试到边缘超时（实测约 125 秒后 504），期间客户端停在“保存中”并可能耗尽连接池。`tests/sql.test.ts` 锁定该状态码。
- CAS 被拒绝时保留该次变更的**表单输入**（`DraftOrigin`）与编辑器草稿标签。冲突路径会先尝试自动三方合并（见下），只有无法自动合并时才需要用户决定；恢复在线或瞬时错误可手动重试。
- 冲突后先做**三方合并**（base = 最近一次与后端一致的快照，local = 含排队改动的本地快照，remote = 最新云端快照）：按实体逐条比较，本地改动叠加到云端结果上，云端不相关的改动全部保留；只要没有同实体冲突，就自动以新 `revision` 再次 CAS 提交，用户无需操作（两台设备都从空板开始、id 完全不同时也不会丢新增项）。
- 同一实体双方都改动且结果不同时**不猜测**：保留云端值，把本地意图作为草稿保留，并明确告知需要人工确认。绝不整板覆盖，也绝不静默丢弃用户改动。
- 顺序（上移/下移）也算改动：本地改过顺序就用本地顺序；双方改成了同一顺序视为一致；双方改成不同顺序记为冲突。本地新增项保持它在本地列表中的位置。
- base 可能落后于后端（保存已落库但客户端没收到成功响应）。此时若某实体在 local 与 remote 都存在、base 里没有、且两侧内容不同，则记为冲突而不是当作本地新增——否则会覆盖另一台设备的改动。
- 顺序冲突也可恢复：「重新打开编辑器」会把这次移动重放到最新版本，而不是写回旧整板；目标任务已被删除时明确告知并保留草稿。
- 自动刷新（标签页获得焦点、恢复联网）在**存在未保存改动**（在途 / 排队 / 失败保留）时直接放弃刷新，读取 ref 判断而不是 React state，避免闭包过期导致把刚失败的改动连同草稿一起丢掉、界面还显示“已保存”。只有用户明确点“丢弃草稿”才会丢弃未保存内容。
- 冲突后**不做整板回写**。界面提供“重新打开编辑器”（`/reopen`）：它先刷新到最新 `revision`，刷新失败或会话变化就中止；目标已被删除时不静默改成新建，而是保留草稿并告知。离线时拒绝提交并保留输入。
- 这是小型个人应用的单用户单行快照上限（`ponytail: 每用户 JSONB/CAS；若数据量或协作增长，升级为按实体的规范化 mutation`）。

## 身份、安全和部署

- 网页真实模式使用 Supabase 邮箱/密码登录，不提供公开注册或重置 UI。第三方客户端通过 Supabase OAuth 2.1 和 `/oauth/consent` 授权页取得自己账号的看板访问权。缺少 Vite Supabase 配置时显示诚实的设置页，用户必须显式点击 LOCAL DEMO；云错误不会静默切 demo。
- SQL 不再依赖单例 owner 配置；RLS 策略要求 `personal_boards.owner_uuid = auth.uid()`。私有表不授予客户端任何权限，读写只能经由 SECURITY DEFINER RPC；首次读取按当前 `auth.uid()` 幂等创建空板，保存只能更新当前用户行。`tests/sql.test.ts` 验证多个用户各自读写、互不可见、匿名拒绝和伪造归属失败。所有 SECURITY DEFINER 函数固定 `search_path`，检查 `auth.uid()`，撤销 `PUBLIC/anon` 执行权限。
- Demo 数据只使用 demo 专用 localStorage key，永不上传。

## Agent 与账户管理

- 远程 MCP 以 2026-07-28 正式规范为基准，兼容 2025-11-25 等旧版；支持完整看板操作，查询不自动顺延。客户端可动态注册，用户确认整账号授权后持续有效，直到主动撤销。
- `/account` 提供授权撤销、30 天回收站、90 天审计。删除按一次保存的集合恢复，不改写存活对象关联，不重启计时器；原项目缺失时可明确指定新归属和日期。只有有效直接用户会话能永久清除。
- 一次最多 100 个操作原子提交；无关对象修改可合并，同对象冲突停止。基准快照通过短期签名读票绑定用户与客户端。幂等请求 ID 防止网络重试重复创建。
- MCP 入口用公开 JWKS 本地验证 JWT，不把入站令牌发送给数据或用户信息 HTTP API。008 迁移提供专用 PostgreSQL 角色与固定操作分派器，凭据独立且不可读表、永久清除或执行任意 SQL；TLS 始终验证证书。
- OAuth 的资源 audience、用户、活动 session 和 consent 在数据库边界核对；即使直接调用已有 RPC 也不能绕过撤销、回收站或审计。
- MCP 每用户 + OAuth 客户端每分钟最多 120 次请求，007 迁移提供原子数据库计数；超额响应 429 和 Retry-After。授权页面禁止嵌套，浏览器跨域可读取 OAuth 挑战头。
- 关键验证在 `tests/agent.test.ts`、`tests/mcp-protocol.test.ts`；部署与工具契约见 [MCP.md](MCP.md)。LOCAL DEMO 仍保持独立的本地演示，不提供云端授权与回收服务。

## 写入保护

- 快照校验在客户端与数据库两侧执行同一组规则；SQL 校验必须显式处理 `NULL`（`item->>'x' is null or ...`），否则缺失字段会被 `NULL` 短路而放行。
- ISO 周键用 `private.valid_week_key()` 校验真实存在的周（例如 `2021-W53` 不存在），而不是只看正则格式。`endWeekKey` 同样校验，并按 `collate "C"` 比较必须晚于 `weekKey`（定宽周键按字节比较才等于按时间比较）。`endDateKey` 先校验格式再转 `date`，用 `date_trunc('week')`（ISO 周一）判断与 `dateKey` 同周。
- 类型校验按 JSON 类型而非文本：`checked` 必须是真布尔、`durationMinutes`/`elapsedMs` 必须是真数字、集合与形状用 `is distinct from`。只做文本比较会放行 `"true"` / `"0"` 这类字符串，让数据库存入客户端拒绝加载的快照。
- 可选键按 JSON 值校验（`private.valid_optional_id` / `private.valid_optional_timestamp`）：键缺失才合法，显式 JSON `null` 与空/纯空白字符串同样非法。`->>` 会把 JSON null 读成 SQL NULL 而当缺省，必须用 `jsonb_typeof` / `#>>` 判断。
- 标题与名称的空白/长度判定与 JS 语义对齐：`private.is_blank()` 覆盖制表符、NBSP、FEFF 等 `String.prototype.trim()` 会去掉的字符（`btrim` 默认只去空格）；`private.utf16_length()` 按 UTF-16 码元计数，与 `String.prototype.length` 相同（例如 160 个星号面字符在两侧都是 320）。
- 上级关联必须是同域顶层任务：SQL 同样拒绝 `upperTaskId` 指向子任务，与 `validateSnapshot` 一致。
- 校验强度两侧对齐：文本型字段（id/name/title/note/domain/color/status/schemaVersion）按 JSON 类型校验，`cycleId` 只与周期数组比对（不与任务 id 混用），因此数据库与客户端对同一快照判定一致。目标是两侧都不更宽松；若未来出现分歧，宁可数据库更严格（fail-closed）。
- `history` 字段自 `004_remove_task_history.sql` 起不在契约内：数据库既不要求也不校验它，客户端 `validateSnapshot` 读取时丢弃它。因此旧快照里残留的该键既不会被拒绝，也不会被回写（落盘的是校验后的规范快照）。`004` 必须先于新版前端执行，因为 `003` 的校验器仍要求该键是数组。
- 客户端 bundle 只允许 `VITE_SUPABASE_` 前缀的环境变量（`envPrefix`），避免无关 `VITE_*` 变量被内联。
- 演示模式是本地共享状态，写入通过浏览器原生 Web Locks 串行化，避免两个标签页互相覆盖。
- `supabase/migrations/001_private_board.sql` 至 `005_project_task_scope.sql` 与 `009_weekly_span.sql`、`010_daily_span.sql` 的迁移链由 `tests/sql.test.ts` 在真实 Postgres（PGlite）中执行验证。`005`、`009`、`010` 须先于新版前端部署；只更新校验器，不改写已有快照、revision、CAS 或 RLS。旧校验器不认识 `endWeekKey` / `endDateKey` 会不加校验地放行；旧前端规范化快照时会丢掉跨度，所以新版发布后不要回退前端。
- 正常的直接操作（删除、勾选、排序、计时、重排等）仍通过快照 CAS 保护，但不创建表单草稿；保存中的反馈只在底部状态栏（`● 已保存` / `○ 待保存` / `✗` / `⊘`）。只有失败或离线时，提示符上方才出现带 `[重试]` `[加载最新]` `[重新打开编辑器]` 的提示行（等价命令 `/retry` `/sync` `/reopen` `/discard`）；表单来源会在最新版本上重新走一遍逐步编辑，直接操作冲突则先确认、加载最新状态后由用户明确重做。

## 终端界面

整站就是一个 shell，但不是日志：每条命令相当于先 `clear` 再执行，屏幕上只有当前场景。看板、登录、账户与 OAuth 授权页共用同一个终端外框（`ShellFrame`），不再有弹窗、面板或拖拽。

- **一个输入面**：提示符（`Prompt`）既是命令行，也是所有表单。`/` 开头是命令；不带斜杠的文字直接新增到当前视图（行尾可带 `#色`、`^上级编号`，专注视图可带时长）。新增、编辑、删除确认、项目管理、OAuth 授权都在同一行里一步一步问，`Esc`/`Ctrl+C` 取消。确认一律 `[y/N]`，空回车即否。
- **登录**：`/login` → `login:` → `password:`。密码不回显（字与光标都透明，只留不动的块光标），不进历史，提问结束即清空；同一表单里带隐藏的用户名字段，浏览器密码管理器可用。失败回到同一提示符重试并保留邮箱。
- **没有滚动区**：一屏固定高度，文档不滚，只有场景区滚。冻结的旧视图是过期快照，看板随时可以重画，所以不留回滚。命令按类型处理：
  - 切场景（`/goals` `/week` `/day` `/focus` `/project n`）换掉场景；
  - 改数据（勾选、新增、`/mv`、`/rm`…）原地重画当前场景，改动的行闪 1.6 秒（`changedIds` 对比提交前后；排序不改内容，单独标记）；
  - 查询（`/help` `/status` `/project`）的长输出整页盖住场景主体，场景头留着，`Esc` 或下一条命令收起——规则是多于 3 行或含键值行；
  - 多步提问（`/edit`、`/login`、删除确认）不动场景，被问到的行由光标标出；
  - 提示符上方只保留上一条命令的回显与结果，短结果与回显同排。`/clear`（`Ctrl+L`）清掉它。
- **场景头**：面包屑（项目 › 周 › 日，可点）、项目时间轴（`━` 已过、`─` 未到、`●` 今天，正在看的那段高亮）、随视图变化的条带（日/专注：这一周 7 天及每天的 `●○`；周：项目内各周；目标：各项目）。运行中的计时器挂在右上角（专注视图除外：右栏就是它）。条带取代了旧的标签页，点格子只就地切换选区。
- **地址栏**：场景写成 `#/day/2026-10-04@<项目 id>`（`@-` 为未归属）。换视图 `pushState`、同一视图里换日期 `replaceState`，后退回到上一个视图；刷新或书签按地址落地。加载完成、选区按地址落定之前不回写，免得被默认场景覆盖；只认 `#/` 开头的形状，不碰 Supabase 回跳的 `#access_token=`。
- **编号**：行首编号描述当前选区的显示顺序——`g1` 目标、`w1` 周、`d1` 日、`f1` 专注块、`d1.1` 子任务；裸数字指当前视图。编号不写进数据，换选区就重新编号。顶层任务按「可见上级」分组（上级在上一层的显示顺序决定组序，未关联的排最后，组内保持存储顺序），所以编号与树从上到下的顺序一致。专注块同理，按它挂的日任务的顺序编号，挂不上的排最后。
- **关联是画出来的**：每个视图都是同一棵「目标 → 周 → 日」树，用 `├─ └─ │` 连。日视图：今天的事挂在本周计划下，本周计划挂在目标下（上下文行灰显、无勾选框，点一下跳到它的视图）；周视图：本周计划挂在目标下，右侧七格 `●○` 是它落到了哪几天；目标视图：右侧是它拆到了哪几周。上级不在本选区（别的周、已归档）当作未关联；没有任何关联时不画「未关联」这一层。不再有单独的 `/tree` 视图：每个视图本身就是树。
- **连线不断**：框线字符纵向占 -400…1120（1.52em），所以行高定为 1.5、行间不留内边距。连线格 `contain: size` 不撑行高，被拉伸到整行后用重复的 `rest` 填满折行、备注与展开的操作区，多余部分裁掉；对齐依赖 Maple Mono CN 半角 600 / 全角 1200 的严格 1:2。
- **排序只在组内**：`/mv up|down|top|bottom` 与冲突后的重放都走 `reorderInScene`，只和同组相邻的一条换位；跨组换位在树上看不出变化。组内第一条再上移会如实提示「已经到头了」。
- **专注视图**：左右两栏。左边是日视图那棵树，每件日任务下面挂它这一天的专注块（标题与任务相同时改写状态：`进行中`、`已结束 09:42`）；挂不上的块（未关联、关联到别的项目或别的日子的任务）收在最后的「其他专注」组，专注块跨项目共享，换了项目也看得见。行尾读数只有一条规则：没结束的写还剩多少（没开始就是计划时长，超时写 `+mm:ss`），结束的写实际用时。
  - 右边是一块钟，只跟着全局唯一的计时器（不论记在哪天），不跟光标：有计时在跑时是它的剩余——模拟表盘是一块随时间被吃掉的扇形，数字是 3×5 像素倒计时（一个像素两个 `█`）；没有计时时是看板时区的现在几点，下面是当天已专注 / 计划时长与下一块。面板里不画到目标的链，左边的树已经画着。`/clock analog|digital` 切换，偏好只存本地。
  - 表盘用象限方块（`▘▝▖▗▀▄▌▐…█`，一格 2×2 像素）画：盲文点阵在 Maple Mono 里点小、格间距大，画出来是散的；方块与像素数字一样在行高 1.2 时上下相接。面按超采样覆盖率点亮，线沿线取最近的像素，细横线才不会落在两行像素之间消失。字号随右栏宽度（容器单位）缩小，字宽取整到整像素，剩下的细缝用同色 0.3px 描边补上。
  - 场景不足 72 列时不分栏，钟收成树上方的两行（标题、进度条与读数）。
- **点击即命令**：行内操作（编辑、子任务、上移/下移、顺延、开始计时、删除）、侧栏、面包屑与条带都可以用鼠标，除勾选与条带外都通过同一个执行器运行等价命令并回显，鼠标用户也能顺手学会键盘。
- **导航模式**：空提示符按 `Esc` 进入，`j/k` 移动光标行（反色）、`x` 勾选、`Enter` 展开、`e` 编辑、`s` 子任务、`J/K` 排序（取代拖拽）、`r` 顺延、`p` 开始/暂停专注（对着正在跑的块或它的任务是暂停）、`S` 结束专注（小写 `s` 留给子任务）、`⌫` 删除、`g/w/d/f` 切视图、`h/l` 翻页、`.` 回今天、`/` 回到提示符。光标一回到输入框就是命令模式；有整页输出时，`Esc` 先收起它。
- **Finder**：`⌘K` / `Ctrl+K` 或 `/find`，模糊查找视图、项目、任务与专注块，回车跳到它所在的视图并选中。
- **配色**：深色 `#141413`、浅色 `#faf9f5`，默认跟随系统，`/theme dark|light|auto` 覆盖并持久化；`index.html` 按配色提供两个 `theme-color`。
- **账户页**：连接地址、已授权应用、回收站、审计按块列出，`/revoke n`、`/restore n`、`/purge n`、`/more trash|audit [prev]` 操作；授权页把唯一的决定放进提示符：`允许「应用」读写你的整个看板？[y/N]`。重定向仍只允许 https 或本机 http。

### 文本与数据边界

- 主界面仅预览标题最多 2 行、备注最多 5 行；备注保留换行与缩进，连续英文或 URL 也可折行；展开行显示完整备注。仅显示截断，不改写保存文本。任务标题／备注上限 450／3000 个 UTF-16 码元，编辑提问与两侧校验一致；专注块标题仍为 300。
- 既有云端须先执行 `003_task_text_limits.sql` 再发布前端；此迁移只放宽任务文本边界，不改写数据，不改变 CAS、RLS 或其他校验。
- 顺延标记（`←09-20`、`←W38`）沿归档条目的 `rescheduledTo` 链回溯到最早的那条记录，显示任务的原放置；不新增快照字段，旧数据也能显示。
- 计时超过上限的运行中计时器在暂停/结束时会截断到上限，保证仍能正常结束。
- 关联候选先匹配项目，再比较「上级所在域」的放置（周←项目、日←覆盖那一周的周任务，跨周任务在它占的每一周都可选）；编辑时已有关联即使不在当前周也保留在候选中。改了日期或周次，候选按新放置重算（跨天日任务按它所在的那一周）。
- 只有顶层任务能改日期／周次（子任务跟随父任务）；`moveDailyTask` / `moveWeeklyTask` 连同子任务一起搬，越界时提示先调整项目范围。`/mv <ref>` 给单点（`W45`、`fri`、`+1`）时整段平移、保持长度，给区间（`W41..W43`、`mon..wed`）时按区间重设，首尾相同收成单周/单天；编辑器的日期、周次字段直接写目标区间。跨天区间或平移后出周时明确拒绝并提示改用周计划。

### 日期与周次写法

输入只有一套规范写法，界面显示用同一套写法；被统一掉的别名（`now` `.` `this` `本周` `tmr` `monday` 单字 `一` `周天`、裸数字周次 `41`、`2026W41`、`10/06` `10.06`，以及 `~` `→` `到` 和连字符区间）一律报错，报错里列出规范写法。

- **日期**：`2026-10-06`、`10-06`（`10-6`）；`today` `tomorrow` `yesterday` / `今天` `明天` `昨天`，相对真实的今天；`mon`…`sun` / `周一`…`周日`，锚点所在 ISO 周里的那一天；`+N` / `-N`，从锚点起的天数。
- **周次**：`2026-W41`、`W41`（大小写都行，必须带 `W`）；`+N` / `-N`，从锚点起的周数；任何日期写法都可以，取那一天所在的周（`today` 就是本周）。
- **区间** `A..B`（只用于 `/mv` 与编辑器；`/day` `/week` `/focus` `/defer` 只接受单点）：两边可以有空格；B 以 A 为锚点——`+N` 从 A 数，星期几落在 A 那一周，省略年份取 A 之后第一次出现；B 早于 A 无效。
- **锚点**是正在改的那个东西：`/day` `/week` `/focus` 用正在看的那天／那周；`/mv`、`/defer`、编辑器用任务当前的起点（新建用正在看的）；项目开始日期用原来的开始，结束日期以开始为锚点、按区间终点补年份；回收站恢复用看板时区的今天和本周。
- **省略年份**：单点取离锚点最近的一年（年底写 `W01`、`1-2` 是明年，年初写 `W52`、`12-30` 是去年）；区间终点与项目结束日期取锚点之后第一次出现，为此跨到下一年只在半年之内成立（`W52..W02`、`W40..W10` 可以，`W43..W41` 多半是笔误，报错；更远的请写年份）。
- **显示**：日期与日历年、周次与今天所在周的 ISO 周年相同时省略年份（`10-06`、`W41`），否则带上（`2027-01-02`、`2025-W52`）；区间写成 `A..B`，起点带年份时终点也带。以起点为锚点（编辑器、`/mv` 正是如此），显示出来的文字原样输入能解析回同一个值。格子宽度固定的条带与分布只放短写，完整写法在 `title` 里；URL 与 MCP/Agent 接口仍用完整的 `YYYY-MM-DD` / `YYYY-Www`。
- 删除项目要求联网且没有未保存改动；有计划时必须逐字输入项目名，确认期间版本变化则拒绝，不扩大删除范围。
- `App.tsx` 中不允许出现裸 `new Error('句子')`、`setFlash('句子')` 或硬编码中文：这些文本无法本地化。用户可见失败必须用 `BoardError` + notice code；`tests/i18n.test.ts` 会强制这一点。
- `tests/ui.test.ts` 以源码契约锁定以上约定；`scripts/verify-terminal.mjs` 在 LOCAL DEMO 上端到端走一遍。

## 字体

- 全站（含横幅、表格与进度条）使用自托管的 Maple Mono NF CN，单一字体族，保证等宽网格对齐；`<pre>` 等元素显式继承字体，否则浏览器默认的 `monospace` 会让横幅错位。框线、块字符与盲文转圈字符都在 core 分片里。
- 完整字体按用途切成 core / common / tail / nerd 四片，用 `unicode-range` 按需下载；只有 core（界面必需，约 0.5 MB）预加载，其余异步加载，不阻塞首屏。
- 四片码点互不重叠；界面字符（含 Intl 运行时生成的日期与星期）已固化进 core，因此应用外壳只用 core，既不闪烁也不为首屏装饰下载大分片。
- 字体许可为 SIL OFL 1.1，许可文本随字体分发（`public/fonts/LICENSE-maple-mono.txt`），`tests/ui.test.ts` 锁定自托管、仅 core 预加载、每片都带 `unicode-range` 等契约。

## 「当前」与「选中」

- **“当前”（今天、今天所在的周）与“选中”（正在查看的周期）是两种含义**：选中的标签页加下划线，当前在标签后追加橙色 `•`，二者不共用同一 class。
- 标签与行内日期统一用 `MM-DD` / `Wnn`，跨月查看时不会只剩日号。
- “今天”由一次 `todayInTimeZone(时区)` 得出，随 `/tz` 设置变化；选中别的周或日不会移动“今天”。
- 切换或编辑项目时，保留仍在新范围内的日期；已越界则把今天钳到新范围并同步周。`/day` 跳到项目范围外时停在边界并说明停在哪一天；运行中的计时器提示可以跳到范围外的那一天。

## 提示与语言

- 领域层、存储适配器与领域校验都不生成直接显示给用户的句子：用户可见失败以 `NoticeCode`（`src/notices.ts`）传递并由界面按当前语言渲染。适配器与校验抛出的英文 `message` 仅作诊断（进控制台），不进入界面；`tests/i18n.test.ts` 会检查适配器失败必带已注册 code，且 `App.tsx`/`storage.ts` 不得有裸 `new Error('句子')`（`domain.ts` 仅保留日期/周数学这类内部不变量）。
- `noticeCopy` 与静态界面文案合并进同一份 `copy` 字典，`tests/i18n.test.ts` 强制两种语言键位一致、提示不混入另一种语言，并保证领域层/适配器确实携带 code。
- 冲突与离线分支依据失败种类（`kind`/`code`）判断，不再用提示文本匹配，因此切换语言不会改变行为。
- 连接线由工作区舞台尺寸与行位置实时计算；舞台元素通过 state 传递，保证首次渲染即绘制（父元素 ref 在子布局副作用之后才挂载）。
